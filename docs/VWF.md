# Variable-width font work — 0.1.7

The 0.1.7 local candidate extends the existing proportional 4x font to one complete dictionary prose entry, Red Shield. Three reviewed scroll captures and 1,536 actual glyph draws cover all 434 visible characters across 14 nonempty lines plus the original blank line. The following Japanese entry keeps its byte-exact original font and 13px advances. This selected prose passes display QA; headings/navigation remain Japanese and other gallery layouts still require testing. See `GALLERY_BUILD.md` and `work/ui/runtime/gallery_candidate_validation.en.json`.

The dictionary body uses font mode 4: the call at EE35C routes supported Latin through the shared 4x bank, while native codes retain EAB10. The visible decoder gate and integer cursor hook already present in the 0.1.6 executable cover this path. Original per-resource packed fonts and sorted native charsets remain intact. Appending ASCII to those charsets is insufficient: their native loader skips single-byte characters and constructs capacity from half the encoded byte length. The observed mode-4 route therefore uses the shared Latin bank directly.

The measured dictionary viewport is x=4, y=72, width=330, height=154, with seven visible rows spaced 22px apart. Its line object has a 45-glyph capacity. The rebuilt entry adds six breaks by replacing English spaces only, retaining all wording and original controls at their original encoded offsets. An offset ledger reverses the added breaks to reconstruct the original serialized English byte-for-byte. A conservative 16px destination rectangle checks each non-space glyph; longest extent is 304px and longest line is 43 glyphs. Other gallery types need their own measured widths/capacities.

Of 82 drafted structured gallery prose targets, 80 pass wrapping/container preparation at that width/capacity. TbHelp000 contains native controller symbols and QsHelp000 contains an unaudited control; both reject. This audit excludes separate item/help tables and does not establish rendering coverage for the other 79 prepared entries. Mixed-font symbols, ruby, runtime format expansion and unbreakable overlong words remain outside the wrapper's supported scope.

Live checks verify the complete 188,928-byte shared glyph bank, its lookup table, integer advances and the two relevant gallery hooks. The native regression pairs 32 EAB10 glyphs with their original 32x24 texture uploads and D7FC call arguments, verifying the full original resource font and each uploaded glyph. It makes no claim about D8E4 or GU vertices for the native path. Source glyphs are 64x64 drawn into 16x16 rectangles; captured output remains 480x272 and emulator internal 4x resolution is unverified.
