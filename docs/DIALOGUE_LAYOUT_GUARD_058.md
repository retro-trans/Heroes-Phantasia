# Dialogue overflow prevention and centered-notice routing (0.1.58)

The repeated Zigmarl overflow in `phase/bin/p101050.bin` and `p101051.bin`, reference 30, comes from a mismatch between previous page-level checks and the installed renderer. The renderer keeps the maximum line width across every page of a dialogue owner. The first page's 290-pixel line therefore gives the later 150/130-pixel page a shared half width of 145 pixels. At the final authored pose the original tail ray cannot accommodate that expanded body. Geometry falls back to the native bubble, while text retains its wide shared origin.

The new mandatory guard measures complete owners and checks all pages at every nonzero authored XY key. It models the installed native descriptor half-pixel units, height adjustment and ray clipping, and checks the immutable white interior when fitted geometry declines. It enforces the 32-row owner and 1,024-byte page limits. The inspected corpus contains 1,265 indexed phase, field, battle-result and battle-skit containers, 30,145 references and 29,936 English bodies.

There are 4,606 conservative reflows in 729 resources, adding 3,673 pages. Readback verifies identical glyphs and nonlayout control order, authored scene/tail tracks, resource suffixes and unrelated resources. The refined model confirms 4,588 overflow risks in the original corpus; 18 other conservative reflows remain. Existing word order is preserved. Words too long for a native fallback cell may break across lines without adding glyphs; these cases are recorded in the preparation evidence. Ruby readings remain attached. New page/reveal/pause timing requires gameplay review.

The reported Zigmarl owner now has a 150-pixel maximum width across six pages. Every page fits the original white interior as well, protecting it when fitted geometry declines. Its authored tail endpoint and reverse ray remain unchanged. This is scoped geometry preservation, not automatic portrait-mouth tracking.

Broader native validation caught an independent fill-origin rounding issue. The 0.1.56 helper chooses its origin from the raster-truncated socket rails and checks the actual integer triangle fan. Inspection of `E5010` and `E50CC..E518C` confirms that the other two contour banks form a border triangle strip and do not use a fan origin. Their potentially disjoint integer kernels are therefore irrelevant to fan selection. Vertices and speaker endpoints remain exact. The helper occupies reclaimed code/pool bytes without changing loaded extents.

The new 0.1.52 elevator crash report identifies `EA718/EA810/EA854`, the native mode-two glyph renderer and its font-table search, called at `EE300`. This was the remaining unguarded Latin caller. English glyphs could enter that renderer's native font lookup; routing for ordinary dialogue already selected the Latin font. The 0.1.57 patch adds the same bounded classification for this shared centered-notice path, covering its sole typed caller. Supported glyphs 32..130 except DEL route to `EA45C`; controls and native glyphs retain `EA718`. The 52-byte helper uses reviewed zero-filled retired text storage. Three load-base models verify 260 cases each, unchanged original relocation records, exact unselected memory and zero loaded growth.

The 0.1.58 follow-up adds the notice return address to the small Latin font guard. It retains the three existing caller gates and the native 8-pixel destination size. Sharing one typed address construction lets the four exact gates fit inside the original 128-byte slot. Three independent load-base models exercise 2,600 cases each across sizes, glyphs and old/new callers. There is no loaded growth.

The native crash regression stops the original first-letter route at the failing renderer entry before its unsafe lookup. The corrected dispatch branch completes all 98 supported Latin glyph draws at each of the two native font sizes and checks return/stack/callee-register state. Three native/control fallback cases per size stop at their preserved entry. The installed native regression therefore has 202 cases, including 196 full English glyph draws. This does not reproduce the user's exact invalid pointer or prove the natural elevator event sequence; those remain gameplay checks.

Installed code identity is checked with the debugger's `memory.read` option `replacements=false`. Its default includes temporary JIT run-block opcodes; these are not executable-file changes. All three installed routing spans match the relocated candidate with replacements excluded. The regression restores the original instructions, borrowed stack and registers before resuming the owned emulator.
